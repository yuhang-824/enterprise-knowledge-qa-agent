# 用户、目标、范围与成功标准

## 用户与目标

员工咨询制度或产品FAQ时，需要能回到原文核对的答案。找不到资料、适用范围不清或文档冲突时，系统应说明缺口并追问，不凭记忆或较新日期猜测结论。

输入为问题、可选对话历史、可选用户明确指定制度与范围。材料为合成制度/FAQ，包含文档ID、版本日期、启用状态、范围、主题及原文片段。业务工具提供文档检索、原文读取和证据检查。

交付回答、文档ID与原文引用、资料缺口、冲突和任务状态。CLI为主运行入口，另提供本机验证页面，所有材料同仓库。

## 必验标准

| 要求 | 可核验标准 | 场景 |
|---|---|---|
| 明确答案 | 仅D01有效时，回答30天且引用D01原文 | clear_answer |
| 文档冲突 | D01=30、D02=15，读全后列出冲突并请求确认 | document_conflict |
| 资料外问题 | 补充检索仍无依据，返回资料不足 | out_of_corpus |
| 改写相似问题 | 报账等措辞通过扩展检索找到报销制度 | paraphrase |
| 上下文追问 | 从先前用户问题识别报销领域，读取材料原文 | context_followup |
| 工具失败 | 明确失败，不能把未读取来源当作无冲突 | tool_failure |

额外覆盖替换原文、结论一致后改为回答、用户确认制度、原文明示替代关系、适用范围、无效制度、步数上限、提示注入文本、不可核验资料与产品/年假FAQ。

## 信任和范围

模型负责选择检索、补查、读取、核对、回答或追问动作；程序负责工具权限、来源完整性和引用一致性。对话历史只能提供主题线索，不能授予制度适用权，也不能当作事实引用。

合成目录的主题、active及scope为可信输入元数据，不是企业ACL。当前仅支持四类明确句式的事实抽取和回答模板；未知复杂条款会拒绝猜测，不声称开放域企业问答完成。

默认24步，达到上限明确incomplete并保留Trace和已读来源。真实模型不可用时提供离线Mock，但Mock不能证明真实模型动态决策效果。
